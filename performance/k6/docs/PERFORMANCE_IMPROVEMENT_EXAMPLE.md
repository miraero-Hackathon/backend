## 개선 내용과 가설

- 관찰 내용: Baseline에서 부하 증가에 따라 p95와 RDS CPU, 읽기 지연시간이 함께 증가했습니다.
- 개선 가설: 거래내역 조회 조건에 적합한 인덱스를 추가하면 조회 범위가 줄어 p95와 RDS CPU가 감소할 것입니다.
- 변경 내용: 조회 조건에 사용되는 사용자 ID와 거래 일시 컬럼에 복합 인덱스 1개를 추가했습니다.
- 예상 지표: p95, p99, RDS CPU와 읽기 지연시간 감소
- 변경하지 않은 조건: SQL 결과, 애플리케이션 로직, 테스트 Profile과 데이터

## 사전 확인

- 변경 전 실행계획: 전체 테이블 스캔, 예상 조회 행 수 10,000
- 변경 후 실행계획: 복합 인덱스 사용, 예상 조회 행 수 850
- 기능 검증: 동일 요청에 대해 응답 데이터가 변경 전과 동일함을 확인

실제 문서에는 `EXPLAIN` 결과 전체를 무조건 붙이기보다 사용 인덱스, 접근 방식과 예상 조회 행 수 등 판단 근거를 요약합니다.

## 테스트 환경과 부하 조건

- 애플리케이션 서버: Baseline과 동일
- 데이터베이스: Baseline과 동일
- 관련 데이터 건수: 사용자 10명, 거래내역 10,000건
- 기준 workload: 5 → 10 → 20 VU
- 실행 조건: Baseline과 동일한 시나리오 및 Think Time 사용
- 실행 간격: 각 실행 사이 5분, CPU와 DB 연결 수 회복 후 재실행

## 결론

- 최종 판정: 개선안 채택
- 가설 검증 결과: 인덱스 적용 후 p95가 23.2% 감소했고 RDS CPU와 읽기 지연시간도 함께 감소하여 가설을 지지합니다.
- 실패율 및 기능 회귀: 확인되지 않음
- 고려할 비용: 쓰기 시 인덱스 갱신 비용과 추가 저장 공간이 발생함
- 적용 결정: 조회 빈도가 쓰기 빈도보다 높고 개선 효과가 명확하여 적용
