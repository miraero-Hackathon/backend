## Run 1 해석

- 모든 API 요청과 응답 검증이 성공했고 설정한 임계값을 통과했습니다.
- p95는 228.37ms로 여유가 있지만 p99는 900.78ms로 1초 기준에 가깝습니다.
- 최대 응답시간 2.54초가 관찰되어 평균값만으로 성능을 판단하지 않고 꼬리 지연시간을 계속 확인해야 합니다.
- RDS CPU가 약 49%까지 올라가고 FreeableMemory가 낮아, 이후 개선 실험에서는 SQL 실행계획과 RDS 메모리 지표를 함께 비교합니다.
- 전체 결과의 399개 interrupted iteration은 시나리오 단계 전환 중 중단된 반복으로 보이며 API 실패율에는 포함되지 않았습니다.

## Run 2 해석

- Baseline 측정 구간은 2026-08-20 16:56:15~17:06:15 KST이며 전체 실행은 17:07:15에 종료됐습니다.
- 실패율은 0%이고 p95 238.82ms, p99 860.08ms로 모든 임계값을 통과했습니다.
- Run 1과 비교하면 실제 평균 RPS는 0.55% 감소했고 평균 응답시간은 7.75%, p95는 4.58% 증가했습니다.
- 반면 p99는 4.52% 감소해 지표별 방향이 일치하지 않습니다. 현재 차이는 반복 실행에서 발생할 수 있는 변동 범위로 보고 Run 3 결과를 기다립니다.
- 최대 응답시간은 4.10초로 Run 1보다 길지만, p99와 실패율이 악화되지 않았으므로 소수의 극단값으로 판단됩니다.
- RDS CPU는 Run 1과 비슷한 약 50% 수준이었고, SwapUsage는 이전 실행 이후에도 증가했습니다.
- EC2 CPU는 최대 약 49.3%, 메모리는 약 74%로 즉각적인 포화 상태는 아니었습니다.
- EC2 디스크 사용률이 약 74.3%에서 83.9%까지 증가했으며, 사후 확인 결과 Tomcat 로그 누적이 원인이었습니다.

## Run 3 해석

- Baseline 측정 구간은 2026-08-20 17:13:09~17:23:09 KST이며 전체 실행은 17:24:09에 종료됐습니다.
- 실패율은 0%이고 p95 250.36ms, p99 986.62ms로 임계값을 통과했습니다.
- p99가 1초 기준에 약 13.38ms만 남겨 두고 있어 꼬리 지연시간의 여유는 크지 않습니다.
- RDS CPU는 최대 약 49.3%로 이전 실행과 유사했고, 읽기/쓰기 지연시간도 최대 약 1.5ms 수준이었습니다.
- RDS SwapUsage는 약 161.5MB에서 164.1MB까지 증가해 세 실행 동안 누적 증가 추세를 보였습니다.
- EC2 디스크 사용률이 약 94.2%에 도달했습니다. Tomcat 로그 디렉터리가 11GB를 차지했으며 로그 정리 후 루트 디스크 사용률은 97%에서 38%로 회복됐습니다.
