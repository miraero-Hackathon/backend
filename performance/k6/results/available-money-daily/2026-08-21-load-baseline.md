## 기본 정보

- 테스트 일시: 2026-08-21 09:35:39~13:18:31 KST

- 측정 상태: Run 1~3 완료, Baseline 확정

## 테스트 목적

- 개선 전 API 성능과 인프라 사용량을 비교 기준으로 남깁니다.
- 실제 운영 트래픽이 아닌 탐색 테스트 결과를 바탕으로 200 VU를 기준 workload로 사용합니다.
- 동일 조건으로 3회 실행하고 주요 지표의 중앙값을 최종 대표값으로 사용합니다.

## 테스트 환경

- 애플리케이션 서버: DEV EC2, Nginx -> Tomcat 9
- 데이터베이스: Amazon RDS for MySQL
- 테스트 계정: 서로 다른 테스트 계정 200개
- 인증 방식: `setup()`에서 계정별 로그인 후 Access Token 전달
- 요청 데이터: 사용자별 목표 ID 사용
- Think time: 반복 요청 사이 1초
- 애플리케이션 커밋 및 인스턴스 사양: 확인 후 추가

## 실행별 해석

### Run 1

- 실패율 0%이며 p95 208.40ms, p99 897.27ms로 임계값을 통과했습니다.
- 세 실행 중 평균 응답시간과 p95가 가장 높지만 여전히 기준 이내입니다.
- 최대 응답시간 2.45초가 있어 평균값과 함께 꼬리 지연시간을 계속 확인해야 합니다.

### Run 2

- 실패율 0%이며 p95 146.85ms, p99 750.35ms로 세 실행 중 가장 좋은 응답 지표를 보였습니다.
- 실제 평균 RPS는 187.24 req/s로 세 실행 중 가장 높았습니다.
- Run 1과의 차이가 있어 단일 실행값보다 3회 중앙값을 대표값으로 사용하는 것이 적절합니다.

### Run 3

- 실패율 0%이며 p95 154.79ms로 안정적이지만 p99는 971.51ms로 1초 기준에 가깝습니다.
- 최대 응답시간은 2.54초로 세 실행 중 가장 높습니다.
- p95와 처리량은 Run 2와 비슷하지만 p99 변동이 커 꼬리 지연시간 개선 여부를 별도로 비교해야 합니다.
